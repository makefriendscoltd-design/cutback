# 음성 기준 브이로그 릴스

확정된 사례는 `videos/day1-sc-vlog/edit-plan-v5.json`이다. 새로운 작업은 같은 레이어 구조와 리듬을 재사용하되 대사·헤드카피·클립 수는 새 내용에 맞춘다. 다른 레퍼런스나 사용자 수정이 우선한다.

## 편집 기준

- 시간축은 문맥·성공한 발화가 정리되고 반복·말더듬·불필요한 여백이 제거된 음성 마스터다. 기존 마스터를 찾아 원본과 연결을 확인하고 고정한다. 스타일 수정 중 무음 삭제·재컷·배속을 다시 하지 않는다. 새 음성 편집은 요청 범위와 프로젝트 규칙을 확인한다.
- 단어 타임스탬프와 실제 발화로 짧은 한국어 구절 자막을 만든다. 자막 수, 오디오 연결 지점 수, 영상 컷 수는 서로 다르다. 영문 레퍼런스 WPM을 한국어에 적용하지 않는다.
- 영상 전환은 문장의 의미와 리듬으로 잡는다. 레퍼런스 58.6초/26컷은 초안 추정 근거일 뿐이다. 49.6초/23컷을 새 작업에 고정하지 않는다. 짧은 도입 뒤 보통 1–3초, 필요한 장면은 더 유지한다.
- 제공한 5초·10초·32초 영상은 필요한 소스 in/out만 골라 쓴다. 이 브이로그 방식은 한 촬영 파일의 서로 다른 유효 구간을 여러 컷에 쓸 수 있다. 필요한 최종 컷 수와 필요한 원본 파일 수를 따로 보고한다. 실제 내용과 안 맞는 장면을 사실 증거처럼 사용하지 않는다.
- 사용자 요청으로 카카오톡 등에서 확보한 파일은 원본 이름·경로·해시를 기록한다. 기존 완성본과 촬영 재료를 구분한다. 대화방에서 다운로드한 권한은 메시지 발송 권한이 아니다.

## 화면과 출력

[production-profile.json](references/production-profile.json)이 재사용 기본값 정본이다. 작업 `edit-plan.json`의 명시적 값은 해당 작업의 재정의다.

- 내레이션 한 트랙 + 음소거 촬영 영상 + 구절 자막 + 선택적 헤드카피를 독립 레이어로 둔다. 자막 교체마다 영상이나 제목을 바꾸지 않는다.
- 말 자막은 위에서 약 44.6% 중심, 흰색 한 줄과 진한 검정 그림자. CSS 글자 크기와 OCR 실측 글자 높이는 다르다. 기존 v1은 위치보다 크기가 작았고, v5의 확대된 한국어 자막은 레퍼런스 폰트와 정확히 같다는 뜻이 아니다.
- 헤드카피는 먼저 현재 작업·이전 세션의 사용자 확정 문구를 찾는다. AI가 제안한 문구를 승인된 문구로 바꾸어 기록하지 않는다. 새 카피가 필요한 때만 관련 글쓰기 스킬을 적용한다.
- 이 사례의 헤드카피는 `POV: AI 미친자가` / `저지른 일`, 첫 1초, 상단과 중앙 사이. 두 줄은 같은 크기의 굵은 흰 글자, 검정 외곽선·그림자다. 별도 검정 화면이나 고정 사각 패널을 넣지 않는다. 이 문구를 다른 주제에 자동 복사하지 않는다.
- 기본 출력은 **세로 4K 2160×3840, 30fps, MP4 high**다. 1080×1920 기준으로 디자인하고 렌더의 `--resolution portrait-4k`로 비율을 유지한다. 낮은 해상도의 촬영 재료가 네이티브 4K 디테일로 복원되었다고 말하지 않는다.

## 제작 실행

`hyperframes` 및 필요한 도메인 스킬을 읽고 기존 작업이면 BRIEF와 편집 소스를 이어간다. 새 작업은 [실행 계약](references/implementation.md)을 읽는다.

생성기는 plan의 시간축·미디어 길이를 검증하고 HTML을 만든다. 원본/폰트/GSAP 파일은 호출자가 제공한다. 카카오톡 조작·전사·음성 편집·임의 카피 생성은 이 스크립트가 하지 않는다.

```bash
python3 .agents/skills/vlog-reference-edit/scripts/build_composition.py --plan /absolute/job/edit-plan.json --composition /absolute/job/composition
```

기본 출력 실행기는 프로필을 읽어 전체 check → 4K 렌더 → 해상도·fps 검증을 수행한다.

```bash
python3 .agents/skills/vlog-reference-edit/scripts/render.py --composition /absolute/job/composition --output /absolute/job/final-4k.mp4
```

작업 composition에서 전체 check 후 렌더한다. 사용자 제작 요청으로 렌더가 이미 승인되었으면 중간 승인 질문을 반복하지 않는다. 단순 스킬 설치만 요청한 경우 새 콘텐츠 제작을 자동 시작하지 않는다.

```bash
npx --yes hyperframes@0.8.36 check
npx --yes hyperframes@0.8.36 render --quality high --resolution portrait-4k --output ../final-4k.mp4
```

## 검수·전달

- ffprobe로 실제 2160×3840/30fps/길이/오디오를 확인한다. 설정값만으로 4K 출력 성공이라 하지 않는다.
- 전체 디코딩, 컷별 대표 프레임과 움직임, 자막 글리프·넘침·그림자, 헤드카피 두 줄 동일 크기와 등장/퇴장 경계를 확인한다.
- 인코딩 오디오와 마스터의 길이·파형 일치를 검사한다. 실제 청취를 하지 않았다면 청취 검수는 미검증으로 남긴다.
- 편집 가능한 plan과 생성기를 수정하고 새 버전으로 렌더한다. MP4나 파생 HTML만 직접 고치지 않는다.
- MP4 링크와 실제 검수 결과를 전달하고 기본 앱으로 연다. 원본 영상·음성·폰트가 Git에 없으면 로컬 재료가 필요한 소스 커밋임을 명확히 한다.
