# AI 학교 레퍼런스 편집

사용자의 목적은 원본 인물 영상을 받아 선택한 레퍼런스의 속도·타이포·애셋 문법을 적용한 완성 MP4를 전달하는 것이다. 분석 문서만으로 실제 편집을 완료했다고 하지 않는다.

## 정본과 스타일 선택

기본형은 `references/styles.json`의 `default_style`로 지정된 v19다. 새 AI 학교 인물 낭독 영상도 별도 스타일 지정이 없으면 기본형을 바로 적용한다. 현재 v19 후속 편집은 `references/styles.json`의 `latest_intro_and_transition_override`를 이전 사례보다 우선 적용한다. 4K 납품은 `delivery_export`를 따른다. 저장소의 이 스킬을 정본으로 관리하며 설치 경로는 이를 참조한다.

[references/styles.json](references/styles.json)이 재현 파라미터와 사용자 요구의 유일한 편집 정본이다. 이 파일의 `evidence_root` 아래 6개 원본·시간 앵커·측정값이 있다. 폰트 후보, easing, 패딩 등 재현 시작값을 원본 실측 설정값이라고 부르지 않는다.

- `info-cards`: R01/R02, 정보 카드 + 하단 인물. 두 원본 중 하나를 고르고 해당 변형을 유지.
- `proof-top`: R03, 상단 증거 삽입 + 고정 인물.
- `numbered-talk`: R04, 고정 제목 + 빨간 번호 + 한글 대사. 애셋 없는 인물 원본에 가장 직접 적용 가능.
- `classroom-proof`: R05, 강의실 + 실제 자료 시연.
- `build-diary`: R06, 과정/일상 몽타주. 토킹헤드 한 테이크뿐이면 추가 애셋이 필요하다. 장면 다양성을 AI로 보충할 수 있지만 실제 수업·학생 결과인 척 만들지 않는다.

사용자가 링크/ID를 지정하면 해당 스타일을 쓴다. 스타일 미지정 또는 “기본형” 요청이면 `default_style`을 적용하며 스타일 선택을 다시 묻거나 비교본만 만들고 멈추지 않는다. 새 대본의 의미에 맞게 애셋과 모션을 새로 구성하고, v19의 기존 수치·사례·타임스탬프를 그대로 복사하지 않는다. 새 영상마다 이미 정해진 한글·타이트 컷·배경 변경 허용을 다시 묻지 않는다. 사용자가 완성본을 요청했다면 비교본만 남기고 중단하지 않는다.

## 레퍼런스를 더 받을 때

1. agent-reach의 해당 플랫폼 경로로 원본 영상과 오디오를 확보한다. 원본 URL, 실제 파일 SHA256, 해상도, FPS, 길이를 기록한다. 서로 다른 게시물/커버/추천 영상을 혼동하지 않도록 shortcode를 대조한다.
2. evidence_root의 `tools/analyze_media.py`로 전수 프레임 인덱스, 장면·무음 후보, 혼합 음량, WAV, 표본 시트를 만든다. 호출법은 `--help`로 확인한다. `tools/transcribe.py`는 이번 6개 파일을 대상으로 한 기계 전사 도구이며 새 원본에는 경로/언어를 맞춘다.
3. 전체 흐름 표본과 컷/자막/키프레임 경계의 연속 프레임을 실제로 본다. PTS는 컨테이너/seek 오프셋과 대조한다. 모든 프레임을 인덱싱한 것과 모든 프레임을 육안 검수한 것을 구분한다.
4. 선택한 원본의 `visual-analysis.md` 형식으로 타이포(실제 글자 bbox와 폰트 크기 구분), x/y 정규화 좌표, 스트로크/그림자, 애셋 종류/겹침/정렬, 컷/모션 시작·끝을 기록한다. 정확한 폰트·곡·스템·원본 easing은 근거 없으면 null/미확정.
5. 새로운 문법이면 새 스타일을, 같은 문법이면 기존 스타일의 reference variant를 추가한다. 단순히 링크 수만큼 중복 스킬을 만들지 않는다.

## 헤드카피·모션그래픽·전체 타이밍 필수 대조

실제 제작 전 [references/event-benchmark.md](references/event-benchmark.md)를 읽는다. styles.json의 새 요구는 필수다. 현재 analysis_completeness가 pending인 항목을 정밀 분석 완료로 취급하지 않는다. 선택한 원본의 빠진 타이밍 분석을 먼저 채우고 제작한다.

## 실제 원본 편집 순서

1. 선택한 스타일 JSON과 해당 원본 visual-analysis.md만 읽는다. AI 학교 내용은 [references/school-context.md](references/school-context.md)의 기존 정본을 필요한 만큼 확인한다. 레퍼런스의 주장/가격/CTA를 새 영상에 복사하지 않는다.
2. 원본은 보존하고 별도 출력 폴더에 STT 단어 시간표와 EDL을 만든다. 반복된 앞 발화/미완성 테이크를 제거하고 마지막 완성 발화를 남긴다. 숫자·고유명사·부정어와 의도적 반복은 음성과 대조한다. 앞부분을 기계적으로 삭제해 뜻을 바꾸지 않는다.
3. 무음을 타이트하게 연결하되 자음·받침·말 끝을 자르지 않는다. 단어 타임스탬프+VAD+실제 청취로 결정한다. BGM이 깔린 전체 믹스의 silencedetect 0개를 발화 공백 0으로 해석하지 않는다. 불연속 클릭 방지용 짧은 crossfade는 대사 중첩을 만들지 않게 한다.
4. 제거/유지 구간과 원본→출력 시간 매핑을 먼저 확정하고 자막·애셋·SFX 시각을 전부 매핑한다. 원본 타임스탬프를 편집 후 영상에 그대로 쓰지 않는다.
5. 헤드카피는 새 대사의 문제·반전·약속에 맞춰 작성하고 레퍼런스의 화면 점유·줄바꿈·글자 형태·등장/유지/퇴장을 대조한다. 기존 학교 고정 카피를 무조건 얹지 않는다. 이어서 선택한 스타일로 한글 의미 청크를 구성한다. 한국어는 영어 단어 단위 자막보다 길어질 수 있으므로 폰트 축소보다 청크 조정을 우선한다. 폰트 이름으로 일치 판정하지 말고 실제 렌더 글자 모양·폭·높이·기준선을 비교한다.
6. 레퍼런스의 B-roll이 모션그래픽이면 새 내용에 맞는 카드·도표·UI·타이포를 실제 애니메이션으로 제작한다. 정지 이미지에 일괄 줌을 주는 것으로 대체하지 않는다. 그림컷·자막 교체·모션 키프레임·SFX를 별도 이벤트로 작성한다. 계열에 하드컷만 관찰되면 임의의 whoosh/줌/바운스를 덧붙이지 않는다. 실제 BGM/SFX를 청취 확인하지 못했다면 원본 일치라고 보고하지 말고 제안 트랙으로 표시한다.
7. AI 배경/조명은 사용자 허용 범위다. 얼굴·입모양·목소리·손/인물 정체성을 보존하고 머리카락/손의 경계 떨림, 그림자 방향, 시간상 일관성을 검수한다. 매 프레임 독립 생성으로 깜빡임을 만들지 않는다. 이미지 수정은 imagegen, 합성/영상화는 실제 사용 가능한 도구로 처리한다.
8. 렌더는 hyperframes 진입 스킬과 실제 footage recut을 지원하는 워크플로를 사용한다. 기존 cutback의 STT/retake/ASS/ffmpeg 기능은 source helpers로 재사용 가능하지만 고정 간격 줌·단일 자막 스타일을 모든 계열에 강제하지 않는다. 기존 수정 중 파일은 덮어쓰지 않는다.
9. 최종 MP4를 디코딩 검사하고 길이/오디오·영상 트랙/해상도/자막 끝/AV sync를 확인한다. 실제 시작·중간·끝과 제거된 반복 발화 주변을 재생·청취한다. 스킬 구문 검사만으로 완성본 재현을 입증하지 않는다.
10. MP4 + 편집 가능한 프로젝트/EDL + 교정 SRT/ASS + 사용 애셋 기록을 전달하고 기본 앱으로 연다. 새 촬영본으로 렌더·청취하지 않은 항목은 미검증으로 명시한다. 수정 피드백은 선택 스타일의 버전에 반영하되 다른 계열의 외형을 섞지 않는다.

외부 게시·메시지 발송은 이 편집 요청의 범위가 아니다. 외부 공개 한국어 카피를 새로 쓰면 brain-council과 humanize-korean, 외부 사실 주장을 더하면 content-research-gate를 적용한다.
