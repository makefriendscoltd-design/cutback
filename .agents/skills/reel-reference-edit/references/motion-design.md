# 전사에서 새 애셋을 설계하기

매 작업마다 빈 애셋 목록에서 시작한다. 기존 스타일·폰트·코드 도구를 재사용해도 그림·화면·모션의 내용은 이번 자막에서 새로 만든다. 이전 작업의 녹화나 완성 애셋은 예시가 아니라 재사용 금지 대상이다.

## 의미 → 화면 → 움직임

문장마다 효과를 붙이지 말고 시청자가 이해해야 할 변화부터 찾는다.

| 발화가 설명하는 것 | 새로 만들 시각 대상 | 적합한 움직임 예 |
|---|---|---|
| 흩어진 것을 정리 | 해당 내용의 실제 항목·연결 구조 | 요소가 분리된 상태에서 묶이며 관계가 드러남 |
| 만들기·수정·개선 | 발화에 해당하는 전후 결과물 | 마스크 비교, 문제 부분 강조 후 실제 변경 |
| 입력이 결과로 바뀜 | 해당 입력·처리·결과의 전용 구성 | 입력이 들어가고 결과가 생성되는 순서 |
| 특정 위치·기능 | 새 대상 화면과 정확한 앵커 | 포인터 이동, 해당 대상에 붙는 콜아웃 |
| 단계·순서 | 발화에 실제로 있는 단계 | 번호→제목→그 단계의 실행·결과 |
| 추상적인 경험 | 그 경험의 구체적인 사물·상황 | 의미 있는 대비·거리·크기 변화 |

표의 레이아웃을 템플릿처럼 복사하지 않는다. 자막을 읽고 각 장면의 구성과 재료를 새로 결정한다. 예시를 넣을 때는 어떤 발화를 무엇으로 설명하는지 밝힌다. 원문에 없던 수치·서비스 성과·조건을 새 사실처럼 넣지 않는다.

## 애셋 설계표

각 항목을 `edit-plan.json`의 asset/beat에 연결한다.

- `created_for_job`: 이번 작업 식별자.
- `authored_source`: 새로 만든 편집 가능한 소스 경로. 완성 MP4만 남기지 않는다.
- `spoken_evidence`: 실제 captions의 번호 또는 시간과 인용.
- `explanatory_purpose`: 자막을 반복하는 대신 무엇을 이해시키는지.
- `visual_concept`: 주 대상, 구성, 주요 크기, 사용하는 새 재료.
- `motion`: 초기 상태→행동→결과, 유지와 퇴장. 실제 길이는 발화에서 정한다.
- `provenance`: 외부 원재료가 있으면 원출처·권리와 새 창작물 내 용도. 이전 영상용 애셋을 이름만 바꿔 넣지 않는다.

이 필드가 있다는 것만으로 새 창작이 증명되지는 않는다. 실제 소스와 렌더 화면을 확인한다.

## 동작 구현

- 글자·도형·마스크·선·클리핑·시점 변화를 표현의 도구로 사용한다. 등장 모션만 있고 그 뒤 의미 변화가 없는 정지 카드들로 채우지 않는다.
- 처음부터 끝까지 흔들기, 모든 장면에 동일한 줌, 무관한 whoosh는 기본값이 아니다.
- 자료를 읽는 시간이 필요하면 움직임을 멈춰 결과를 보여준다. 발화 리듬에 맞춰 짧은 인물 단독 구간도 남긴다.
- 콜아웃/추적은 화면 속 실제 대상의 위치를 따라가야 한다. 고정 좌표 효과를 실제 모션 트래킹 작업이라고 부르지 않는다.
- GSAP/HyperFrames 타임라인은 임의 시각으로 seek해도 같은 상태가 나와야 한다. 실제 브라우저 조작을 기록하는 애셋은 별도의 고유 녹화로 만든다.
- 래스터·촬영 영상의 원해상도 한계와 4K 출력은 구분한다. 가능하면 새 애셋은 실제 출력 상자 해상도에서 렌더한다. 타이포·벡터를 1080p에 먼저 굽고 확대하지 않는다.
- AE 앱 없이 만든 결과는 'After Effects 스타일 효과'로 설명한다. `.aep` 납품을 대신했다고 주장하지 않는다.

## 시각 검수

동일한 UI 틀에서 문구·색상·크기만 바꾼 연속 장면은 재검토한다. 작업 화면을 반복해야 한다면 완성 결과, 수정 전후, 실제 동작, 다른 관찰 위치처럼 설명 역할을 바꾼다. 애셋 수를 맞추기 위한 순환 배치를 하지 않는다.

승인된 애셋 상자 안에 놓은 실제 렌더로 검수한다. 주 대상이 바로 식별되고, 중요한 움직임이 사용되는 구간 안에 발생하며, 상단 카피와 하단 전사 자막이 경쟁하지 않아야 한다. 파일·프레임 해시 검사는 동일 파일/동일 화면 검출에만 쓰고 디자인 품질 판정으로 대신하지 않는다.
