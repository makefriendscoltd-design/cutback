# 메모지형 — 새 애셋·모션그래픽·4K 릴스

공식 호출 이름은 **메모지형**이다. “메모지형으로 제작해줘”는 이 스킬을 선택한다. 내부 식별자는 `reel-reference-edit`를 유지한다.

완료 산출물은 실제 검수한 MP4와 편집 가능한 소스다. 준비 파일이나 계획만 만들고 끝내지 않는다. 임의의 길이·화면비·주제를 가진 입력에 적용하되, 다른 스타일을 명시한 요청은 우선한다.

## 바뀌지 않는 것과 매번 새로 만드는 것

**재사용:** 출력 비율, 애셋·자막 배치, 폰트·검정 그림자, 렌더·검증 도구.

**새로 제작:** 해당 영상의 실제 발화를 설명하는 그림·도형·화면·카피·모션. 이전 영상에 쓴 애셋·녹화·완성 컴포지션을 가져와 재배치하지 않는다. 학교·커피·포스터 등 과거 사례의 주제나 파일을 새 작업 기본값으로 넣지 않는다. 같은 템플릿의 색과 문구만 바꾼 화면을 여러 개 만드는 것도 목적에 맞지 않는다.

- 상단: 발화를 이해시키는 부연 자료와 짧은 가이드. 하단 자막의 축약본을 한 번 더 띄우는 곳이 아니다.
- 하단: 실제 발화와 시간이 일치하는 전사 자막. 요약·카피로 대체하지 않는다.
- 전용 **모션그래픽 제작이 우선**이다. 마스크 리빌, 도형·타이포 모션, 대상에 붙는 콜아웃, 수정 전후 변화 등으로 발화의 의미를 보여준다. 웹사이트 녹화는 실제 인터페이스를 설명해야 할 때 새 재료로 확보한다.
- 출처·제작용·자료 이미지 배지는 화면에 넣지 않는다. 실제 자료인지 새 설명용 창작물인지 내부 계획에 기록하며 실제 성과·배포 서비스라고 주장하지 않는다.
- 한 완성 영상에서 같은 보조 영상 파일을 반복하지 않는다. 이름·인코딩·크롭만 바꿔 중복을 피했다고 하지 않는다. 같은 대상이 다시 필요하면 다른 설명 역할과 화면·동작을 새로 만든다.

## 크기·음성 계약

정본은 저장소의 `reference-styles/2026-09-13/memo-vs-yellow-title/style-profile.json`이다. `output_defaults`가 출력, `production_layout`이 승인된 배치다. 관찰 사실과 제작 기본값을 혼동하지 않는다.

- 기본 출력은 **2160×3840, 30fps**. 레이아웃은 정본의 1080×1920 설계 좌표를 두 축에 동일하게 2배 적용한다. 새 텍스트·벡터는 4K에서 직접 렌더한다. 완성된 1080p 영상의 확대만으로 4K 그래픽 제작을 대신하지 않는다.
- 애셋 바깥 상자와 자막 위치·크기는 유지한다. 새 인물의 화면비와 머리 위치는 본편 리프레이밍으로 맞춘다. 원본을 가로·세로로 비균등하게 늘리지 않는다.
- 이 프로젝트의 음성은 **이미 꼬리물기 편집된 마스터**를 사용한다. 순서·간격·길이·속도 고정. 원본 촬영본만 있다면 기존 편집 마스터를 먼저 찾는다. 찾지 못했으면 미확인으로 남기며 임의 재컷하지 않는다.
- 길이, 자막 수, 의미 구간 수, 애셋 개수는 입력에서 결정한다. 과거 영상의 길이나 21개 슬롯을 고정하지 않는다.
- 명시적인 다른 해상도·스타일 요청은 작업 override로 기록한다. 일반적인 이 스타일 요청에는 승인된 메모지 레이아웃을 쓴다. 노란 번호형을 명시하면 별도 관찰값을 참고해 구현하고, 메모지 전용 빌더가 그 모드를 구현했다고 주장하지 않는다.

## 실행

기존 작업이면 BRIEF·edit-plan과 최신 사용자 수정부터 읽는다. 처음 받은 원본은 `project-resume-brief`와 프로젝트 연속성 규칙으로 이미 진행 중인 같은 작업을 확인한다. 승인 인터뷰를 다시 시작하지 않는다.

1. `hyperframes`를 진입점으로 사용한다. 타임라인은 `hyperframes-core`, 렌더는 `hyperframes-cli` 계약을 따른다. 기존 auto_editor 전체 파이프라인은 음성 재컷·BGM·줌을 바꿀 수 있으므로 실행하지 않는다.
2. 원본, 고정 음성, 실제 전사 자막을 확보한다. 준비기·빌더·검증기 사용은 [production.md](references/production.md)를 따른다. 원본만으로 전사와 창작이 끝났다고 하지 않는다.
3. 전체 자막을 읽고 의미 단위를 나눈 뒤 **이번 영상만의** 애셋 설계표를 만든다. 각 애셋에 연결 자막, 부연 목적, 디자인, 움직임, 진입·퇴장 시점, 새로 만든 편집 소스를 기록한다. [motion-design.md](references/motion-design.md)를 읽고 발화 의미에 맞춰 선택한다.
4. 직접 애셋을 제작한다. SVG/HTML/GSAP 등 편집 가능한 소스에서 의미 있는 동작을 구현하고, 필요하면 독립 영상으로 먼저 렌더한다. 래스터 이미지가 필요한 경우 `imagegen`, 명명된 모션 효과·컴포넌트는 `hyperframes-registry` 및 `hyperframes-animation`을 사용한다. 외부 사실을 새로 주장할 때만 리서치 게이트를 적용한다.
5. `edit-plan.json`을 정본으로 본편·새 애셋·상단 카피·하단 자막을 연결한다. 구운 자막과 SRT는 동일한 captions 데이터에서 생성한다. 타임라인에 필요한 미디어는 빌드 시 정적으로 선언한다. 런타임 JS에서 video 태그만 생성하면 HyperFrames가 누락할 수 있다.
6. 대표 구간을 실제 출력 크기로 렌더한다. 작은 화면으로 축소해서도 주 대상과 동작이 읽히는지, 본편 위 자막·애셋 상자가 맞는지 확인한다. 파일 해시가 다르다는 이유만으로 화면 다양성이나 디자인 품질을 통과시키지 않는다. 내부 검수 뒤 전체 렌더까지 계속한다.
7. 고정 마스터 음성을 최종 영상에 스트림 복사하고 패킷·PCM 해시와 길이를 검증한다. AAC가 아닌 마스터는 원본 PCM 보존을 우선하고 필요한 인코딩 변경을 기록한다. 자동 BGM·SFX를 추가하지 않는다.
8. 입력에서 산출한 길이·자막, 실제 출력 해상도, 애셋 중복·범위, 전체 디코드와 전 구간 대표 프레임을 검사한다. 직접 청취·입 모양·모션의 실제 속도·원본 대비 좌우 검수는 기계 검사와 별도로 기록한다. 미검증을 통과라고 쓰지 않는다.
9. 최종 MP4와 새 애셋/편집 소스 링크를 주고 기본 앱으로 연다. 요청 없는 외부 게시·업로드는 하지 않는다.

## After Effects 효과라는 말의 의미

기본 경로는 HyperFrames에서 구현하는 After Effects 계열의 시각 효과다. Adobe After Effects를 실제 실행했다거나 `.aep`를 만들었다고 말하지 않는다. 사용자가 AE 프로젝트 자체를 요구하면 설치·실행 가능 여부를 확인한 다음 실제 AE 작업 경로로 진행한다. 효과 이름보다 자막의 대상을 정확하게 설명하는 결과가 우선이다.
